## 3. מבוא

ארגונים מודרניים פרוסים על פני כמה אתרים ותלויים לחלוטין ברשת התקשורת: מערכות ייצור,
דואר אלקטרוני, שרתי קבצים, גישה לאינטרנט ועבודה מרחוק. תקלה ברשת משביתה את העבודה, ופריצה
לרשת עלולה לחשוף מידע רגיש.

מטרת הפרויקט היא לתכנן ולהקים, בסימולטור Cisco Packet Tracer, רשת ארגונית מלאה לחברת
Intel Israel הכוללת שלושה סניפים בערים שונות, המחוברים זה לזה דרך תשתית WAN מבוססת BGP.
הרשת מתוכננת לפי שלושה עקרונות:

1. **היררכיה** — חלוקה לשכבות (Access / Distribution / Core) ותכנון כתובות היררכי, כך שהרשת
   קלה להבנה, להרחבה ולאיתור תקלות.
2. **יתירות** — אין נקודת כשל יחידה בתוך הסניפים: קישורים כפולים, Spanning Tree, EtherChannel,
   HSRP, שרתי DHCP כפולים, ליבה כפולה, וקו גיבוי DSL.
3. **אבטחה** — הגנה בכל שכבה: אבטחת פורטים, DHCP Snooping, BPDU/Root Guard, ניהול ב-SSH בלבד
   דרך VLAN ניהול ייעודי, שרת AAA מרכזי, חומת אש ASA עם DMZ, CBAC, ו-VPN מוצפן בין הסניפים.

הפרויקט מממש את כל נושאי הלימוד של י"ג–י"ד ככל שהסימולטור מאפשר, וכל סניף בנוי בגישה שונה
כדי להדגים חלופות תכנון.

## 5. דרישות הארגון מהרשת

1. חיבור שלושת הסניפים זה לזה ולאינטרנט, עם יתירות בין הסניפים.
2. תקשורת מאובטחת (מוצפנת) בין הסניפים בכתובות הפרטיות, וגישת עובדים מהבית לסניף הראשי.
3. הפרדה בין מחלקות, כך שכל מחלקה ברשת נפרדת (VLAN).
4. המשך עבודה גם כאשר מתג, נתב או קישור בודד נכשל.
5. אתר אינטרנט של החברה הנגיש מהאינטרנט, בלי לחשוף את הרשת הפנימית.
6. רשת אלחוטית לעובדים, ורשת אורחים מבודדת מהרשת הפנימית.
7. ניהול מאובטח של ציוד הרשת, רק מעמדות מנהלי הרשת, עם רישום מרכזי של כל הכניסות והאירועים.
8. שעון אחיד בכל הארגון (NTP), ושירותי DNS, דואר, FTP ו-AAA מרכזיים.
9. סניף אחד מבוסס IPv6 לקראת העתיד.
10. הגנה מפני התקפות פנימיות בשכבה 2 ובשכבה 3.

הטבלה המלאה של כל דרישות משרד החינוך ומיקום מימושן — בנספח `requirements-matrix.md`.

## 6. בחירות וחלופות לדרישות הארגון

| נושא | החלופות | הבחירה בפרויקט ונימוק |
|---|---|---|
| מודל תכנון | Three-tier מול Collapsed core | **חיפה: Three-tier** — אתר גדול, 3 בניינים, צמיחה עתידית. **ירושלים: Collapsed core** — אתר בינוני; שכבת ליבה נפרדת מייקרת ולא מוסיפה. מדגים את שתי הגישות |
| פרוטוקול ניתוב פנימי | OSPF מול EIGRP | **חיפה: OSPF רב-אזורי** (תקני, מתאים לרשת גדולה מחולקת לאזורים). **ירושלים: EIGRP** (התכנסות מהירה עם feasible successor, תצורה פשוטה). **קריית גת: OSPFv3** ל-IPv6 |
| חיבור בניין C | חיבור ישיר לליבה מול חיבור דרך בניין B | חיבור דרך בניין B, המחייב **Virtual Link** — לפי דרישה 22.16. בתכנון אמיתי היינו מחברים ישירות לליבה |
| EtherChannel | LACP מול PAgP | **LACP** בחיפה (תקן IEEE), **PAgP** בירושלים (Cisco) — מדגים את שניהם |
| יתירות שער | HSRP / VRRP / GLBP | **HSRP v2** — נדרש במפורש; גרסה 2 תומכת ב-IPv6. ה-Active של כל VLAN הוא גם ה-Root של STP באותו VLAN |
| DHCP | על נתב / שרת ייעודי / SLAAC | **חיפה:** על מתגי L3 עם Split Scope (יתירות). **ירושלים:** שרת ייעודי + DHCP Relay. **קריית גת:** SLAAC + Stateless DHCPv6 |
| NAT | Static / Dynamic / PAT | **חיפה: Static** לשרת ה-Web ו-NTP + PAT לגלישה. **ירושלים: Dynamic** (מאגר של 6 כתובות — מגבלה שנבדקה). **קריית גת: PAT** |
| חומת אש | ASA מול CBAC / ZBF | **ASA** בסניף הראשי (שלושה אזורים: inside/outside/DMZ). **CBAC** על נתב הקצה בירושלים |
| מי מבצע NAT בחיפה | ASA מול נתב הקצה | **נתב הקצה** — ה-ASA רק מסנן ומנתב, כך שכתובות פרטיות עוברות בו ללא שינוי וה-VPN רואה אותן |
| VPN בין סניפים | IPsec בלבד מול GRE over IPsec | **GRE over IPsec** — Static NAT על שרת ה-Web היה מתרגם את התשובות ל-VPN לפני ההצפנה; תעבורה דרך ממשק Tunnel (שאינו NAT outside) אינה מתורגמת |
| VTP | Server/Client מול Transparent | Server/Client בחיפה ובירושלים (דומיין לכל בניין), **Transparent** בקריית גת. הוסבר סיכון ה-Revision Number |
| ניתוב ל-WAN | פרוטוקול דינמי מול סטטי | **סטטי** בלבד (דרישה 22.17) — לא חושפים את מבנה הרשת הפנימית לאינטרנט |

### מגבלות הסימולטור ופתרונן
| מגבלה | השפעה | פתרון בעולם האמיתי |
|---|---|---|
| אין NAT64 | מחשבי IPv6 בקריית גת אינם מגיעים לשרתי IPv4 בחיפה | NAT64/DNS64 או DMZ ב-Dual-Stack |
| דרישת "סניף IPv6 מלא" מול "NAT בכל סניף" | NAT קיים רק ב-IPv4 | VLAN 199 יחיד ב-IPv4 לציוד ישן, עם PAT (פרשנות שאושרה עם המנחה ✍️) |

## 12. טבלת שמות להתקנים

**מבנה השם:** `<סוג>-<אתר>-<בניין/קומה>-<תפקיד><מספר>`

| קיצור | משמעות |
|---|---|
| R | Router — נתב |
| SW | Layer-2 switch — מתג שכבה 2 |
| SWL3 | Layer-3 switch — מתג שכבה 3 |
| ASA | חומת אש |
| AP | Access point — נקודת גישה |
| SRV | Server — שרת |
| PC / LT / PRN | מחשב / מחשב נייד / מדפסת |
| HFA / JLM / KG | חיפה / ירושלים / קריית גת |
| ISPA / ISPB / ISPC | ספקי התקשורת A / B / C |
| A / B / C | בניין |
| F1 / F2 / F3 | קומה |
| ACC / DIST / CORE / CC | Access / Distribution / Core / Collapsed Core |
| EDGE / BR / PE | נתב קצה / נתב גבול של ספק / נתב ספק מול לקוח |

**דוגמאות:** `SWL3-HFA-A-DIST1` — מתג שכבה 3, חיפה, בניין A, Distribution מספר 1.
`PC-JLM-SAL-03` — מחשב, ירושלים, מחלקת מכירות, מספר 3.

✍️ להוסיף רשימה מלאה של כל ההתקנים (אפשר לייצא מהקובץ).

## 16. פקודות
✍️ לכל סוג התקן — `show running-config` עם הסבר לכל בלוק (ההסברים קיימים בקבצי השלבים):
- מתג Access (למשל `SW-HFA-A-ACC1`): VLANs, Trunk, Port-security, DHCP Snooping, BPDU Guard, SSH, AAA.
- מתג Distribution (למשל `SWL3-HFA-B-DIST1`): HSRP, DHCP, LACP, OSPF + Virtual link.
- Collapsed core (`SWL3-JLM-CC1`): PAgP, DHCP Relay, EIGRP + סיכום.
- `ASA-HFA-FW1`: nameif, security-level, ACL, inspection.
- נתבי הקצה: NAT (שלושת הסוגים), CBAC, GRE over IPsec, Easy VPN.
- נתבי הספקים: BGP, OSPF.

✍️ צילומי 24 הבדיקות מתוכנית הבדיקות (שלב 16, חלק 6), כל אחד עם שורת הסבר "מה זה מוכיח".
